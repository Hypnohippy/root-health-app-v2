# PR #70: authentic Root Health introducer experience

## Product boundary

The introducer's commercial onboarding, agreement, and signature are completed through the existing `/admin/introducers` workflow before demonstration access. This PR does not repeat those steps. Production continues to use its existing app and database. The introducer edition is permitted only on a positively verified, non-Production Vercel Preview deployment connected to the isolated Supabase project; customer Production behavior is unchanged.

No deployment, merge, invitation, migration, or live data acceptance was performed for this local change set. The isolated baseline is reported applied by the earlier independent Preview verification; the local follow-up migration below has not been applied. Current end-to-end behavior against that remote project has not been tested in this session.

## Root-controlled fictional organisation setup

`lib/provisionIntroducerFictionalWorkforce.server.js` is a local idempotent provisioning operation. `POST /api/introducer/root-provision` is available only on the verified introducer Preview, requires same-origin request, a verified Root administrator, an existing UUID grant, and the already-confirmed Auth user attached to that grant. It creates no Auth users, sends no email, does not copy commercial records, and cannot be invoked by the introducer role.

Provisioning prepares one fixed fictional organisation, two fictional units, 24 members without emails or Auth-user links, 24 workforce profiles with null user ownership, and 55 synthetic historical assessment rows across four dates. Eighteen distinct baseline participants and successively smaller matched cohorts produce meaningful movement while respecting the existing five-person reporting gate. Stable IDs and upserts make retries idempotent. The existing grant is mapped to the organisation only after every seed upsert succeeds. Expired, revoked, mismatched, or customer-linked accounts are rejected.

Local tests exercise the entire provision-and-map function against an in-memory Supabase-shaped admin double. They show deterministic synthetic data, retry idempotency, mapping order, and denial cases. This is not a live Supabase provisioning test. Do not call the Root-only endpoint against Preview until its identity, `ROOT_ADMIN_EMAIL`, service-role scope, project ref, and role grant are separately verified and explicitly approved.

## Isolation and safeguards

- Personal evidence is keyed to `auth.uid()` and its exact personal profile; owner RLS prevents cross-user reads and writes. A local forward-only migration requires Root's organisation mapping to activate personal access and checks expiry/revocation on every new DB statement, but it has not been applied to Preview. Personal records are not assigned the fictional organisation. Profile INSERT is deliberately unavailable to clients; trusted Root provisioning creates the private profile before mapping the grant.
- Workforce rows have no real email, Auth user, or individual account association. HR browser responses omit profile keys, email and Auth IDs; direct aggregate requests are grant/org checked and returned data is passed through Root's existing five-participant suppression.
- The existing access grant's expiry and revocation are checked server-side on protected requests and by employer RLS. The applied baseline's personal RLS was owner-scoped but did not independently check grant expiry; the local forward migration adds that check and remains unapplied. Client storage and the virtual Workplace role are navigation hints only, never authorization.
- Distribution, invitations, billing, subscriptions, role changes and customer provisioning remain unavailable to introducers through middleware/API guards and the database allowlist.
- All app routes and API requests remain pointed to the deployment's configured Supabase URL. Preview activation requires its designated Vercel project ID and exact isolated Supabase ref and refuses the known Production ref. Vercel Production is always classified as normal customer mode.
- Audio generation returns 503 when `OPENAI_API_KEY` is absent. No credentials are fabricated or copied.
- `/coach` reuses the genuine Voice Coach interface and WebRTC/data-channel flow. The local PR adds an introducer-only access path requiring the existing verified grant, current mapped fictional organisation, confirmed email, and a separate Root-controlled `voice_coach_enabled` entitlement. Personal context is loaded using the authenticated bearer client. A Body handoff is reloaded by its exact record ID plus verified `user_id`, `profile_key`, and personal (no organisation) scope; Thought Work handoff text is bounded and labelled as user-stated intent, not stored evidence. The unapplied local migration defaults Voice entitlement off and adds a service-role-only atomic quota reservation (one active lease, three starts per rolling 24 hours by default; project spend and per-user limits are configurable). The provisional planned session is 30 minutes with a 15-minute completion grace period and a one-time server-approved extension for an action already in progress; the provider hard expiry is capped at 60 minutes. The route preserves existing customer authorization and the 10-per-hour process-local brake in normal customer mode. None of this has been applied to Preview or tested against a live provider.
- Stripe clients in personal/workplace checkout and webhooks are constructed at request time from the existing secret. Existing configured payment behavior is preserved; an absent key returns the existing route-level unavailable response rather than failing the build at module import.

## Availability and remaining limits

- Genuine Personal Root self-service paths are implemented in local code, but do not collect real introducer wellbeing data until the separate health-data privacy and processing review is approved.
- The sanitized schema intentionally omits subscription and billing tables. Paid-only subscription entitlements/features therefore remain unavailable in this Preview; the virtual demo capability is not a commercial entitlement and cannot create one.
- Root Workplace is a controlled reporting slice using the genuine `/org-insights`, `/executive-review`, and `/launch-kit` routes. The underlying aggregate endpoint is read-only and grant-scoped. Organisation management, HR Coach, learning review records, workforce invitations/imports, interventions/pricing and any feature whose tables or write permissions were omitted are not available to introducers.
- The 24-member history and current 20-table baseline were reported by prior independent Preview verification. The new 24-member customer-shaped fixture and grant mapping have not been applied to or verified in the live Preview. The application is not yet ready for human acceptance or external access.
- `supabase/migrations/20261118153000_pr70_expiring_personal_access.sql` is a local, unapplied follow-up (SHA-256 `6256B26D82617A47BFAFE30F0AF5A8C2B92DD7948AD8AAC1B1B2365B52E59C56`). It adds an invoker-rights helper requiring Root's organisation mapping plus an active, unexpired, non-revoked grant, and tightens personal-table RLS. Its PGlite regression test passes; live REST denial remains unverified.
- A real preview route run, browser desktop/mobile acceptance, direct REST denials, live expiry/revocation, and a live post-provisioning HR response remain outstanding. Local tests and build checks cannot establish those remote properties.

### 19 November local Voice Coach implementation status

This remains **local and unapproved for Preview execution**. There is no platform-wide session-count cap or limit on registered introducers. The proposed initial project budget is **£10 per calendar month in Europe/London time**, with Voice disabled by default, a provisional estimate of $0.20 per provider minute, three starts per introducer per rolling 24 hours, a 30-minute planned session, a 15-minute completion grace period, and a five-minute advance warning. A maximum-duration reservation includes the full 60-minute provider ceiling. Before any reservation is accepted, Root must configure the current month's HMRC published USD-per-GBP rate and its source; the estimate is converted to GBP and rounded up with a configurable 10% FX/settlement margin. Missing or stale-month FX data fails closed. This is a manual, auditable estimation method, not a billing exchange-rate guarantee. At a sample rate of 1.50 USD/GBP, a 60-minute $12 estimate plus the 10% margin reserves £8.80, so the £10 monthly budget would permit at most one such session absent other reserved spend. The figures remain provisional; the budget is shared and per-introducer allocations/duration remain Root-configurable.

Root's protected usage API and Root-only page at `/introducer/voice-budget` report monthly GBP reservations, remaining estimated budget, available provider-reconciled actual cost (currently null unless separately recorded), active session state, and denial reasons. The RPC logs valid-identity session denials. Authentication failures rejected before the RPC are not included in that counter. OpenAI Realtime session creation does not return a final billed cost, so actual cost reconciliation is not currently implemented. App reservations are conservative estimates, not a hard guarantee of total provider charges.

The introducer middleware fails closed for other billable provider routes that do not yet use this shared budget: Root text Coach, Workplace text/voice Coach, transcription, Playbook rewrite, and audio generation. Only the explicit grant-authorised, budget-reserved Realtime session endpoint remains live-capable. This preserves non-AI Personal Root and Workplace routes but means those AI features are unavailable in this Preview until metered. A dedicated provider project/key and provider-side monitoring/reconciliation are also required to prevent spend outside these application reservations from being mistaken for part of the £10 application budget.

No prerecorded clip is currently available. The separate [fictional Voice Coach recording plan](pr70-introducer-voice-recording-plan.md) is ready; producing the reusable clip requires separate approval for a reserved genuine Preview test session. Playback will use static media only and make no inference calls.

### 19 November affordability and introducer availability refinement

The introducer landing page now distinguishes a Root-disabled live Voice entitlement, a paused project policy, incomplete termination controls, and an unavailable access check. If a reservation is denied for the individual allocation or shared monthly estimate, the Voice Coach reports the specific safe reason. The page probes only the static `/introducer/voice-coach-demo.mp4` asset and will render it with a persistent fictional/prerecorded label only when that file exists. No recording is present today; the page clearly says so. Static playback itself makes no inference request. Creating the genuine clip still requires separate approval for one budget-reserved, fictional-data test session and capture.

The call termination receipt is not a usage receipt. Confirmed provider hang-up means the call is no longer active; it does not report final billed audio/text token usage. Therefore the full estimate remains reserved after confirmed termination and after a definitive creation rejection. We must not release the difference merely from elapsed duration or a successful hang-up. Safe early release requires authoritative, per-call final usage/cost evidence and a reviewed Root-only reconciliation process; neither a provider-usage importer nor a settlement RPC exists in this candidate. Until then, Root can reduce the next reservation by configuring a shorter planned duration or lower per-introducer allocation, while preserving the strict monthly project check. This is conservative and may temporarily understate remaining demonstrator capacity.

The £10 monthly estimate is not a hard invoice cap. Other provider-backed routes remain blocked only in verified introducer mode until they share the same durable reservation system: `/api/root-coach` (text Personal Coach), `/api/organisation-coach` (Workplace text Coach), `/api/hr-voice-session`, `/api/transcribe`, `/api/playbook-review`, and `/api/generate-audio`. This leaves non-AI Personal Root and fictional Workplace workflows available; Breath with Root does not start an AI call. Live `/api/realtime-session` is only usable with explicit Root authorization, termination readiness, and a successful project/user reservation. There is no platform-wide introducer count limit.

OpenAI documents that the WebRTC creation response contains a call ID and that the server can end the active call using `POST /v1/realtime/calls/{call_id}/hangup`. The introducer route now requires a valid provider `Location`, stores the call ID in a service-only receipt before returning SDP, and refuses to expose SDP if durable tracking fails. If tracking fails after provider creation, it makes bounded immediate server-side hangup attempts. The browser timer and `expires_at` remain convenience/defense-in-depth only, not the termination guarantee.

The migration candidate adds service-role-only claim/complete/retry and one-time completion-extension RPCs. The extension can move the server termination deadline only to the already configured provider hard expiry; it cannot extend the provider call lifetime or increase the cost reservation. The client warns five minutes before the planned end and enters wrap-up at the planned 30-minute point. An extension is requested only during the final minute of the initial 15-minute completion window when a response or Playbook offer/save/conflict is still pending. Explicit Playbook consent remains required. This is a best-effort graceful completion window; browser scheduling and provider behavior are not transactional, and the absolute 60-minute provider ceiling can still end a consultation if an action remains unresolved.

The scheduled worker claims expired calls and calls whose grants have expired, been revoked, or lost Voice entitlement. It uses `FOR UPDATE SKIP LOCKED` to prevent duplicate concurrent claims, persists only safe error codes, retries with exponential backoff capped at one hour, and retains the reservation/blocks another session until provider termination is confirmed. If a worker crashes after claiming, `terminating` rows become claimable again. Deleted grant or Auth rows do not cascade away the minimal call-control receipt. Root reporting includes pending termination and retry status, without returning provider call IDs.

The worker is `GET /api/introducer/voice-termination`. It requires a timing-safe `CRON_SECRET` bearer check, a positively verified introducer deployment and an exact match between the configured Supabase URL and expected Preview project reference. The proposed isolated deployment config is `vercel.introducer.json`, using Vercel Schedules' one-minute schedule and one-minute jitter. Vercel documents schedules for Preview environments; one-minute jitter requires Pro or Enterprise. This config is local only: Preview branch scheduling, secret configuration, actual invocation timing, provider hang-up and recovery still require isolated acceptance. A one-minute cadence plus up to one-minute jitter gives a nominal detection target of 120 seconds plus provider response time, not a hard maximum: Vercel documents delayed and catch-up scheduled runs, and provider/network failures can extend retries. The absolute provider expiry is the final bound at 60 minutes from call creation, subject to provider enforcement. A provider-create response without a valid call ID or simultaneous provider/database outage during call-ID persistence remains an unresolved orphan-call edge case; the migration's default-off flag prevents Voice from being enabled until authenticated Preview acceptance and operational monitoring address this risk.

The migration is `supabase/migrations/20261119120000_pr70_introducer_voice_entitlement_and_usage.sql`. It keeps grant entitlement, project policy and server-termination readiness disabled by default. Project budget checks, individual allocation edits, and call-ID attachment use the consistent transaction lock order: global project lock, then per-user lock. The local PGlite boundary test still exercises concurrent calls over one connection only. A separate regression test now targets two real PostgreSQL connections, but is gated on a disposable loopback `PR70_LOCAL_POSTGRES_TEST_URL` database and was not run in this environment. No provider call, migration, Preview scheduler or Preview database change was performed.

The local candidate preserves the genuine Voice Coach prompt, authenticated Personal Root evidence, Body/Mind handoff, consultation flow and existing client-side Playbook consent/save workflow. Voice remains unavailable until the scheduler is configured, the migration and identities are independently reviewed, true multi-connection quota tests pass, and authenticated Preview tests prove duration/revocation termination and retry recovery.
